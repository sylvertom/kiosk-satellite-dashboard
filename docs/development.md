# Development

The page is plain HTML, CSS and JavaScript: no build step, no dependencies, no
`package.json`. What is in the folder is what Home Assistant serves. The tools need
Node.js 22 or later, and Google Chrome for the checks; Python 3 only to add icons.

## How the code fits together

`index.html` loads the scripts in order with plain `<script>` tags. `js/ha.js` defines
`window.HA`, the connection; `js/core.js` creates `window.Kiosk`; every file after it is
a function that runs once, as it loads, and:

1. takes what it needs from `Kiosk` at the top (`const { el, icon, watch } = K;`), only
   names from files above it in `index.html`, which have already run;
2. reaches a file below it at the time of the call instead (`K.openPopover(cfg)`), as
   that file has not run yet when this one loads;
3. adds what other files use at the bottom (`Object.assign(K, { makeTile })`) and keeps
   the rest to itself.

So the top of each file lists what it depends on, and a `K.` call marks a dependency on a
later file. Two values are decided at boot by `js/main.js` and read as `K.shape`
(`'round'` or `'wide'`) and `K.home` (the room this kiosk belongs to).

**Rendering.** A widget registers an update function for the entities it shows with
`watch(ids, fn)`. When Home Assistant reports changes, `render` runs the update functions
of the entities that changed, in one animation frame. Update functions touch the DOM only
when something changed (`setText`, `setClass`, `setVar`). A value the user has just set
is held (`hold`, `held`, `shownPct`) until Home Assistant answers with the entity's next
state.

**Styles.** Sizes are in `rem`, and 1rem follows the short side of the screen, so one
layout fits every screen of a shape. `css/wide.css` and `css/round.css` arrange the
shared pieces under `.shape-wide` and `.shape-round`. Colours, corners and fonts come
from the tokens of `css/base.css`, which a theme changes (see [Themes](themes.md)): use
them rather than a value of your own. Animations move only `transform`
and `opacity`, which stays smooth on an Echo's small GPU. A custom property set from
JavaScript (`--p`, `--side`, `--size`…) is named in a comment where the stylesheet uses
it.

## Trying it without Home Assistant

```sh
node tools/mock-ha.mjs            # serves the page at http://127.0.0.1:8123/
```

Open `http://127.0.0.1:8123/index.html?device=Echo+Spot+Bedroom` in a browser, tap the
"sign in" pill (the mock accepts anything) and play with the lights. The mock keeps light
groups in sync with their members, runs the projector scripts, answers the WLED and media
player services, and stands in for Music Assistant's library (favourite radios and
playlists with made-up covers) and for two calendars, their events placed on the day the
page asks from. It signs in as Home Assistant does: a login's token runs
out after half an hour, and a refused token ends the connection. It serves
`config.example.js` as `config.js`; `--config config.js` serves yours instead, though the
mock only knows the example's entities.

## The check suite

```sh
node tools/mock-ha.mjs &
node tools/shoot.mjs              # Google Chrome; elsewhere than macOS set CHROME=<path>
```

It drives headless Chrome with touch events at 480×480, 960×480, 960×600 (an Echo Show 8
as Kiosk Satellite lays it out) and 1280×800 against the mock and prints `ok` or `FAIL` for each of its checks, over 500 of them. The example's
background pictures come from Unsplash: the suite fetches each once and hands it to the page, or a made-up
one when there is no network. It saves its screenshots to `screenshots/`, which git
ignores; `--docs` also refreshes the pictures in `docs/images/` (the README's and the
[theme gallery](theme-gallery.md)'s), so do that only when the documentation should show
a change. The suite leaves out XP's wallpaper if you added one, so its pictures show XP as
everyone gets it. A run that crashes leaves
its Chrome running: `pkill -f kiosk-shoot-`.

GitHub runs it too, on every push to `main` and every pull request
(`.github/workflows/checks.yml`), on macOS like the checks that measure text. A run that
fails lists its failures at the top of its page and keeps its screenshots.

The suite is the safety net for every change: add checks for what you build, in the file
of `tools/checks/` for that part of the page, and keep the mock's entities in step with
`config.example.js`, which is the suite's configuration too.

What it covers: taps, drags across the dial and along its arc (and the Spot's rim), the
toggles in its middle, the tiles' own sliders, the tiles as rows or as cards in as many
columns as fit (three, four and eight lights on the Echo Show 5 and 8), the panel's sliders, long-presses, the
projector scripts and media card, WLED effects, palette and speed, group members, the
Spot's menu ring (tap and swipe on its tab, picking an item, closed by a tap beside its
items, rings of one to ten buttons sized to fit), the Show's rail, items kept to one
shape, Now playing following a stand-in for Kiosk Satellite's player, the menu folders
on both (a ring with Back in the middle, a grid with Back first), a script and a
favourite reaching the mock with the right player and the toast that follows, Music
Assistant's favourites (asked for as the page connects, for the player's instance, the
switch between radios and playlists, covers and the icon where one is missing or does
not load, none left, ten at most on the Spot's ring, a player that is not Music
Assistant's), a room without a player, a call Home Assistant refuses (the control goes
back to the light's level), the Spot's room list and the Show's room grid with their
light counts, a room's power button (which leaves another room's light on), a main light whose
members Home Assistant does not list, and *All lights off*, both with seven rooms, the office room, the header on
every screen (including one too narrow for its mode names), the Spot's arrangement, its
rim reaching the edge and the swipe through its lights, sensors going unavailable, a
sensor shown only while its showWhen holds (every form of it), the house's alerts (in every
room, alone in the Spot's row, first on the Show, in each theme's warning colour), every
theme on both shapes (its files loaded, its text legible on its background, no layer much
larger than the screen, a clock of one width), a scene whose script comes after the page
has shown, a kiosk's own theme, a name in the address that is not a theme, the accent
following the light the dial controls (and staying legible on both schemes), Settings on
both shapes (following the light turned off and on, the version, the list of themes, every theme
switched in place looking as on a fresh page, a scene stopped and started again, a theme
picked before the last one's files have come, what the kiosk keeps across a reload, a
kept theme since removed, a kiosk's own theme as its default), the rooms'
pictures (each room's own, none, one that does not load), the gradients drawn instead
(from a colour, the accent following the light, its opposite, none on a mono theme), the login round-trip, a token
in the address being ignored, a login's token renewed before it runs out and when Home
Assistant refuses it, a refused kiosk token, and the rooms' events (the page's clock set
to 10:00: what Home Assistant is asked, their order, the count, the Spot's line and the
Show's tile and a swipe through them, the panel and Open calendar, an event added, none,
a calendar that does not answer, each period, the list's lines and length).

All of that runs in desktop Chrome, which has far more memory and speed than an Echo:
try a change on a kiosk as well (Synthwave's first grid looked right here and starved
the Spot's graphics memory).

## Icons

`python3 tools/fetch_icons.py sofa-outline ceiling-fan` adds icons to `js/icons.js`
(it never removes any). The list at the top of the script is the set the page itself
uses.

## Changes and releases

Each change goes on a branch of its own and into `main` through a pull request, which
runs the checks; `Fixes #12` in its description closes the issue it answers. A change
that someone using or setting up the kiosk would notice adds a line under **Unreleased**
in [CHANGELOG.md](../CHANGELOG.md), saying what they will see, and what to add to
`config.js` if anything. Leave the `?v=` alone: the release sets them all.

A release is numbered `major.minor.patch`: a fix bumps the last number, something new the
middle one. For 1.2.0:

```sh
git switch -c release-1.2.0 main
node tools/release.mjs 1.2.0          # every ?v= to 1.2.0; Unreleased becomes 1.2.0
git commit -am "Release 1.2.0" && git push -u origin release-1.2.0
# once its pull request is merged:
git switch main && git pull && git tag v1.2.0 && git push origin v1.2.0
```

Every file asked for at a version it never had is what makes the kiosks fetch them again,
and Settings shows that version. The tag starts `.github/workflows/release.yml`: it checks
that the files and the changelog are at that version, zips the `kiosk/` folder to copy to
`/config/www/` and drafts the GitHub release with the changelog's section as its notes.
Read the draft on GitHub and publish it.
